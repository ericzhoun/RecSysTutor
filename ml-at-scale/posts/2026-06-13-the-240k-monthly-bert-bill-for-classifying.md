billion per day</p><p>Peak throughput: 28,000 requests per second</p><p>Average: 15,000 requests per second</p><p>Peak: 32,000 requests per second</p><h3>The ML Pipeline</h3><p>The system uses a DistilBERT-based classifier for text and a separate ResNet-50 for images. Both models are fine-tuned on a dataset of 4 million human-labeled examples. Ground truth is provided by an external contractor team of 150 labelers. Every Sunday, the training and evaluation sets are refreshed by sampling 50,000 new examples from the previous week’s flagged content, which the contractors re-verify.</p><h3>Current performance</h3><p>End-to-end P99 Latency: 55ms</p><p>Model Accuracy (F1-score): 0.92 (reported by internal eval set)</p><p>False Negative Rate: 4 percent (reported by internal eval set)</p><p>Costs:</p><p>Inference Infrastructure: $240,000 per month</p><p>Labeling Operations: $115,000 per month</p><p>Total: $355,000 per month</p><p>Recent incidents:</p><p>Incident 1: A 31 percent surge in user-reported policy violations over 18 months, despite the model evaluation metrics remaining flat. No alerts triggered because the system believed it was performing within spec.</p><p>Incident 2: A 4-hour partial outage in June caused by the UserReputation service timing out, which defaulted the gateway to Allow-All mode, flooding the platform with unmoderated content.</p><h1>The Analysis</h1><p>Now let me show you what is actually happening here.</p><h3>Critical Issue #1: The Evaluation Loop Death Spiral</h3><div class="pullquote"><p>I write about ML systems in production — the tradeoffs, the architecture decisions, the stuff that doesn’t make it into papers. If you want to go deeper, the paid tier covers the technical details I can’t fit in free posts.</p></div><div class="paywall-jump" data-component-name="PaywallToDOM"></div><p>Looking at the ML Pipeline section, notice how the training and evaluation sets are refreshed weekly by sampling from the previous week’s flagged content and sending it to the same 150 contractors. Over 18 months, those contractors became aware that their labels directly dictated what got removed. To reduce the volume of appeals and internal pressure, they drifted toward labeling borderline content as safe. Because the evaluation set is drawn from this same biased pool, the model’s reported F1-score stayed at 0.92 while the actual real-world false negative rate climbed 31 percent. The system is grading its own homework using a biased teacher.</p><h3>Critical Issue #2: The Synchronous Reputation Bottleneck</h3><p>In the Architecture Overview, the UserReputation Service adds 30ms of synchronous latency to every single post. This represents over 50 percent of the total P99 latency (55ms). If this service hangs, the whole moderation chain stalls. More importantly, using a synchronous lookup for historical user data on every post submission is an architectural anti-pattern that limits horizontal scaling of the ingest service.</p><h2>Critical Issue #3: Feature Leakage via Reported Metrics</h2><p>The Content-Feature-Store includes a feature for current user-report-count on the post. Since the model is retrained weekly on flagged content, it has learned that if a post has already been flagged or reported by users, it is more likely to be a violation. This creates a feedback loop where the model waits for human reports to become confident, rather than proactively identifying violations based on the content itself. This explains why the false negative rate is so high for new content that hasn’t been seen by users yet.</p><h3>Critical Issue #4: Over-Provisioned GPU Inference for Low-Signal Content</h3><p>The system runs Policy-BERT (12ms) on every single post, regardless of length or content type. At 15,000 requests per second, they are spending $240,000 a month on GPU clusters. Looking at the traffic, a significant portion of these posts are short-form content like “lol” or “good morning” which could be filtered by a $500-a-month CPU-based Regex or FastText model. They are using a sledgehammer to crack every nut.</p><h3>Critical Issue #5: Fail-Open Vulnerability</h3><p>As seen in Incident 2, when the UserReputation service fails, the system defaults to Allow-All. This is a massive security hole. For a content moderation system, a failure in a dependency should trigger a Fail-Closed (or Fail-to-Human-Queue) state for high-risk accounts, rather than a total bypass of the safety layer.</p><h1>WHAT I D DO INSTEAD</h1><h3>1. Independent Gold-Standard Audit</h3><p>Impact:</p><p>Detects labeler drift within 7 days.</p><p>Reduces real-world false negative rate by an estimated 25 percent.</p><p>Trade-offs:</p><p>Increased labeling cost for a specialized, high-accuracy “Gold Team.”</p><p>Requires a more complex data pipeline to manage two separate labeling streams.</p><h3>2. Tiered Inference Architecture</h3><p>Current: Every post → Sentinel-V3 (BERT)</p><p>New: Every post → FastText Classifier (0.5ms) → If high confidence safe, stop. If low confidence, → Sentinel-V3 (BERT).</p><p>Impact: 15,000 rps on GPU → 3,500 rps on GPU.</p><p>Trade-offs:</p><p>Adds complexity to the model deployment pipeline.</p><p>Slight increase in P99 for the 20 percent of posts that require both models.</p><h3>3. Asynchronous Context Injection</h3><p>Replace: Synchronous UserReputation lookup ($0 additional cost).</p><p>With: The Reputation service pushes updates to a local cache or the Gateway includes the reputation score in the JWT/Session header during the post request.</p><p>Total: $0 (reallocating existing infrastructure).</p><p>Trade-offs:</p><p>Reputation scores might be slightly stale (seconds or minutes).</p><p>When this is the wrong call: Only if the system requires millisecond-perfect consistency for financial transactions or high-stakes identity verification.</p><h1>The Impact</h1><p>Before redesign:</p><p>System blind to 31 percent increase in violations.</p><p>$355,000 monthly cost.</p><p>After redesign:</p><p>Proactive violation detection with independent ground-truth verification.</p><p>$185,000 monthly cost (48 percent savings).</p><p>Time to implement: 3 months, 4 engineers.</p><h1>APPENDIX: Cost Estimation Methodology</h1><p>How I estimated the savings for each decision:</p><p>Solution 1: Independent Gold-Standard Audit</p><p>Baseline: $115,000 / month for 150 contractors.</p><p>After change: $115,000 (standard) + $15,000 (Gold Team) = volume.</p><p>Confidence: High — This is a standard industry practice for labeling quality.</p><p>Solution 2: Tiered Inference Architecture</p><p>Baseline: $240,000 / month for g4dn.xlarge GPU nodes at 15,000 rps.</p><p>After change: $60,000 (reduced GPU footprint) + $5,000 (CPU nodes for FastText) = $65,000 / month.</p><p>Estimated saving: $175,000 / month (72 percent reduction in infra (short text) heavily favors this.</p><p>Solution 3: Asynchronous Context Injection</p><p>Baseline: $0 direct cost, but saves 30ms in latency.</p><p>After change: $0.</p><p>Estimated saving: $0 in
