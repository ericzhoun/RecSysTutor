StreamPulse is a Series C video-first social platform company that recently migrated their core recommendation engine to a Generative RecSys Architecture.

(Don’t know what Gen RecSys is? Check out this beautiful article)

They’ve reached 200 million daily active users (DAU) and are currently managing a repository of 45 million active short-form videos.

Their engineering team built a Generative Semantic Retrieval system that replaces traditional two-stage retrieval (vector search) with a sequence-to-sequence model. This system predicts “Semantic IDs” (discrete tokens representing content clusters) directly from user history. Here’s their setup.

# Architecture Overview

When a user opens the home feed, the system triggers a sequence prediction to generate the next N items the user is likely to engage with.

[](../assets/a1bc5f88020cfcdd.png)

### Traffic patterns:

Daily Active Users: 200,000,000

Total Daily Feed Refreshes: 4,000,000,000

Average: 46,296 req/sec

Peak: 88,000 req/sec

The ML Pipeline:

The model is a 1.2B parameter Transformer-decoder trained on 18 months of user interaction sequences. Items are represented as Semantic IDs generated by an Residual Quantized Variational Autoencoder (RQ-VAE).

This RQ-VAE was trained using the 128-dimension embeddings from the company’s legacy Matrix Factorization model to ensure “backward compatibility.”

The decoding process uses a beam search width of 4 with no temperature sampling.

### Current performance

Inference Latency (p99): 240ms (Autoregressive decoding of 10 items)

System Reliability: 99.8% uptime

Business Impact: 18% drop in session length (measured at week 6 post-launch)

Costs:

GPU Compute (A100 Clusters): $980,000 / month

Data Egress & Storage: $140,000 / month

Total: $1,120,000 / month

Recent incidents:

Incident 1: Feed “Frozen” Bug - Users reported seeing the same 10 videos for 48 hours. Resolved by clearing the User State Store cache.

Incident 2: Inference Timeout Spike - p99 jumped to 1.2s during a regional holiday peak, causing a 5% fallback rate to random popular videos.

# The Analysis

Now let me show you what’s actually happening here.

### Critical Issue #1: Semantic ID Poisoning

 _I write about ML systems in production — the tradeoffs, the architecture decisions, the stuff that doesn’t make it into papers. If you want to go deeper, the paid tier covers the technical details I can’t fit in free posts._

The Architecture Overview notes that the RQ-VAE was trained on embeddings from the “legacy Matrix Factorization model.” This is a classic mistake.

Those legacy embeddings were already heavily weighted toward popular items because Matrix Factorization struggles with the long tail.

By quantizing those specific embeddings into Semantic IDs, they effectively baked 2018-era popularity bias into the very “alphabet” the new GenAI model uses.

This is why 200M users are being funneled into a tiny subset of 2,000 “safe” IDs.

### Critical Issue #2: The Feedback Loop Delay

They reported that engagement metrics looked fine for 3 weeks, then cratered. This is the “Novelty Trap.”

The new model was initially retrieving items that were different from the old model’s top-picks, which spiked CTR. However, because the autoregressive decoding lacks diversity regularization (beam width of 4, no temperature), the model converged on the most probable sequences.

By week 6, the users had seen the entire “high-probability” set of 2,000 videos multiple times. The 18% drop in session length is the direct result of user boredom once the “diversity” of the new model was exhausted.

### Critical Issue #3: Computational Waste in Autoregressive Decoding

The p99 latency is 240ms for just 10 items. In a high-scale feed (46k req/sec), paying for A100s to perform autoregressive decoding to find only 2,000 unique items is an architectural disaster.

They are essentially using a $1M/month supercomputer to perform a hash table lookup. If the output space has collapsed to 2,000 items, a simple heuristic or a linear model could achieve the same result at 5ms latency on commodity CPUs.

### Critical Issue #4: The “Backward Compatibility” Fallacy

The setup mentions the RQ-VAE uses the “legacy ID to Embedding mapping.” This creates a static representation of a dynamic content library. New videos being uploaded today are being forced into “semantic buckets” defined by a model that hasn’t been updated. This explains why the system is failing to surface new, trending content, contributing to the diversity collapse.

### Critical Issue #5: Monitoring the Wrong Signal

They have 99.8% uptime but didn’t catch the diversity collapse until it hit the bottom line. Their “Recent incidents” show they treat “system performance” as “uptime and latency.” In a generative system, the most important health metric is “Output Entropy” or “Intra-list Similarity.” They are flying blind without a real-time diversity metric.

# WHAT I’D DO INSTEAD

**1\. Move to Content-Based Semantic IDs**

Instead of training the RQ-VAE on legacy Matrix Factorization embeddings, I would use a multi-modal approach. Pass the raw video frames and audio through a frozen CLIP or Whisper backbone to generate content-centric embeddings, then quantize those.

Impact:

Discovery of long-tail content increases by 400%.

Elimination of popularity bias at the ID generation level.

Trade-offs:

Requires a significant re-training of the RQ-VAE which can take 2-3 weeks of compute time.

**2\. Implement Stochastic Beam Search with Entropy Penalty**

Current: Beam search width 4 (deterministic/greedy).

New: Stochastic Beam Search with a temperature of 0.8 and a penalty for repeating the same high-level Semantic ID “prefix” within a single user session.

Impact: Session length: 18% drop → 5% increase over baseline.

Trade-offs:

Slightly higher variance in latency (p99 might fluctuate by +/- 10ms).

When this is the wrong call: If the platform was purely transactional (e.g., re-ordering groceries), where users actually want the same high-probability items every time.

**3\. Shift to Parallel Decoding via Medusa-style Heads**

Replace: Autoregressive decoding ($980,000/month GPU cost)

With: A block-parallel decoding architecture that predicts 5 tokens at once, followed by a verification step.

Total: $588,000/month (40% reduction in GPU footprint)

Trade-offs:

Increased complexity in the model architecture and custom inference kernels.
