By the end, every item has a name: a tuple of discrete codes like (12, 41, 7), first code roughly the category, second the subcategory, third the item.</p><p>Learned from what the item is, not from who clicked it. In part 3 a transformer learns to predict items for users.</p><p>Three requirements to build such a model, each one shaping the design:</p><ol><li><p><strong>Unique.</strong> Two items cannot share a name, or it is not an identifier.</p></li><li><p><strong>Hierarchical.</strong> Similar items must share prefixes.</p></li><li><p><strong>Generatable.</strong> The codes must be producible left to right by an autoregressive model. Otherwise where’s is GenAI?!</p></li></ol><h2>The input: text embeddings</h2><p>For each item, concatenate title, brand, category path, and a description snippet into one string, and run it through a frozen pretrained sentence encoder (all-MiniLM-L6-v2). Output: a 384-dimensional vector per item, where semantically similar texts land near each other.</p><p>The encoder was contrastively trained on about a billion sentence pairs; we train nothing here but just reuse.</p><p>No review text goes in. Reviews describe opinions, not identity, and a genuinely new item has metadata but no reviews.</p><p>One subtlety about that input string: Amazon’s metadata includes the category path (”Beauty &gt; Hair Care &gt; Shampoo”), so the human taxonomy is literally part of the text the encoder reads.</p><p>That is a real reason the level-1 codes later align so cleanly with categories: the taxonomy leaks into the embedding. Drop the category field and you still get a hierarchy, built from title and description semantics alone, just a fuzzier one. What goes into the text is our choice, and it shapes what the codes can encode.</p><p>So we have per-item vectors: continuous, 384 floats, unique.</p><p>We need three discrete hierarchical codes now. Let’s build them!</p><h2>Residual quantization</h2><div class="subscription-widget-wrap-editor" data-attrs="{&quot;url&quot;:&quot;" data-component-name="SubscribeWidgetToDOM"><div class="subscription-widget show-subscribe"><div class="preamble"><p class="cta-caption">Liking this? Store the entry’s index instead of the vector: one integer instead of 384 floats, at the price of error.</p><p>Residual quantization runs the trick recursively. Quantize the vector against codebook one. Subtract the chosen codeword; what remains, the residual, is everything code one missed.</p><p>Quantize the residual against codebook two. Subtract. Repeat. Code one captures the coarse shape (”this embedding is skincare-shaped”), each level refines the last. The hierarchy requirement we listed above falls out of quantizing errors of errors.</p><p>The RQ-VAE wraps this in an autoencoder. An autoencoder is two networks trained as one: an encoder compresses the input, a decoder reconstructs it, the loss is reconstruction error.</p><p>Here: encoder MLP maps 384-d to a 32-d code space, three codebooks of 256 codes quantize residuals, decoder rebuilds the 384-d embedding from the summed codewords. If three codes carry enough to rebuild the content embedding, they are a faithful compressed identity.</p><p>Level one quantizes the full embedding, so it can only capture the dominant directions of variance in that space, and in a catalog’s text-embedding space the largest thing separating items is what kind of product they are.</p><p>Level two quantizes what level one missed, the next-largest structure (sub-type, brand family).</p><p>Level three, the residual of that. The tiers are emergent: coarse-to-fine falls out of quantizing residuals. We do not assign meanings to levels; the data’s variance structure does.</p><p>Industry splits on how to fit the codebooks. TIGER trains the RQ-VAE end to end. Kuaishou’s OneRec uses RQ-KMeans, same residual structure, codebooks fit by clustering, trading fidelity for stability at their scale.</p><p>The residual principle is the invariant.</p><p>I built the RQ-VAE: canonical, and its main failure mode is the most useful thing in this article.</p><div><hr></div><h2>Implementation: two lines carry the weight</h2><div class="paywall-jump" data-component-name="PaywallToDOM"></div><p>Full model in <a href="https://colab.research.google.com/drive/17C3s-M_TVuoNoBqLi7YTA7zCMoxoAKvG#scrollTo=098e54bf">Part 2 of the notebook</a>. Encoder 384 to 32, three codebooks of 256, decoder back to 384. Two details matter.</p><p><strong>Codebooks are buffers, not parameters.</strong> Gradients never touch them. Each code’s vector is an exponential moving average of the encoder outputs assigned to it: a code drifts toward the mean of the embeddings that use it. Far more stable than gradient-updated codebooks.</p><p><strong>The straight-through estimator.</strong> Quantization is an argmin; argmin has no gradient, so nothing upstream of it would train. The fix is one line: zq_st = z + (zq - z).detach() Forward pass uses the quantized vector, backward pass pretends quantization was the identity function, so the encoder receives gradients anyway.</p><h2>Codebook collapse (failure mode!)</h2><p>A code is only updated when items are assigned to it. Codes that win early assignments drift toward the data and win more. Codes that start in empty space are never chosen, never move, dead from step one. Rich-get-richer and the equilibrium is a 256-way codebook behaving like a 15-way one.</p><p>You have seen this before: it is k-means’ empty-cluster problem. A centroid initialized in empty space claims zero points forever.</p><p>What makes it dangerous: the loss hides it. The encoder trains jointly and learns to route every item through whatever codes survive, so reconstruction keeps improving the whole time.</p><p>Few live codes, few possible tuples, items pile onto shared tuples, and the dedup token ends up doing the identity work.</p><p>The “semantic” ID degrades into an arbitrary ID and you don’t spot it.</p><p>The notebook shows it twice. First in 2D, where you can see it: 1,000 points in five clusters, 16 codes, the exact EMA update rule.</p><p>Without restarts, the codes that started outside the data sit dead while a few insiders carve up everything. Then at full scale, same tokenizer trained with and without the fix:</p><ul><li><p>with restarts: 247, 252, 246 of 256 codes alive; <strong>11,745 distinct names</strong> for 12,101 items; 356 collisions</p></li><li><p>without: level 1 collapses to <strong>one live code</strong> inside 200 steps; <strong>1,181 distinct names</strong>; 10,920 collisions</p></li></ul><p>Reconstruction loss fell in both runs. One tokenizer can tell twelve thousand items apart by semantics, the other about a thousand.</p><p>The fix: dead-code restarts. Any code whose EMA usage drops below a threshold is re-seeded at a live encoder output from the current batch.</p><p>Same move as re-seeding empty k-means centroids.</p><div
