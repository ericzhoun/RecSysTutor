eras:</p><ol><li><p>Matrix factorization</p></li><li><p>Deep learning (the Two-Tower standard)</p></li><li><p>Generative era</p></li></ol><p>Xavier Amatriain’s RecSys 2025 keynote mapped this evolution well, from Netflix Prize nostalgia to Gemini-powered preference elicitation.</p><p>It was a good talk. </p><p>It was also dangerously optimistic.</p><p>For engineers building discovery systems at scale right now, the path forward is not “add an LLM.”</p><p>It never is.</p><p>The real challenge is distinguishing between what looks cool in a keynote demo and what actually survives contact with a billion users and a 200ms latency budget.</p><p>The industry is buzzing about autonomous agents and “media of one.”</p><p>I’m going to argue that agents are overrated for mass-market products, that personalization must remain bounded to be safe, that the <em>real</em> generative revolution (HSTU, not LLMs) is quietly rewriting the stack, and that real-time adaptation still matters more than anything else.</p><div><hr></div><h2>Agents Are a Distraction for Consumer Products</h2><p>The keynote highlighted “Zero-History Preference Elicitation”: using conversational agents to ask users what they want. Technically impressive. Practically useless for products with billions of users.</p><p><strong>The Cognitive Load Problem.</strong> The success of modern feeds is built on passive consumption. People open TikTok to decompress, not to negotiate with a chatbot about what kind of videos they’re in the mood for.</p><p><strong>The Latency/Cost Barrier.</strong> Running an agentic loop (reasoning → tool use → response) shatters the 200ms latency budget required for seamless feed rendering. At billion-user scale, the inference cost of an agentic layer is not just expensive.</p><p>It is economically ruinous compared to efficient embedding retrieval.</p><p>For niche tasks like travel planning, complex B2B queries, or high-consideration purchases, agents genuinely add value.</p><p>But for mass-media discovery, they are a solution looking for a problem.</p><p>The dominant interface for the next decade will remain a feed, not a chat window.</p><div><hr></div><h2>The Generative Revolution That Actually Matters: HSTU and Sequential Transduction</h2><p>When people hear “Generative RecSys,” they picture an LLM chatting with users about movie preferences.</p><p>The actual generative revolution happening in production looks nothing like that.</p><div class="paywall-jump" data-component-name="PaywallToDOM"></div><p>It looks like Meta’s HSTU (Hierarchical Sequential Transduction Units), a 1.5-trillion-parameter model that treats user behavior sequences as a language in themselves.</p><p><strong>What HSTU actually does.</strong> It reformulates recommendation as sequential transduction. Instead of the classic DLRM pipeline (feature extraction → feature interaction → prediction), HSTU feeds raw behavioral sequences (clicks, watches, skips, purchases) directly into a modified transformer.</p><p>No hand-engineered features.</p><p>No feature crossing. </p><p>Just actions, treated as tokens, predicted autoregressively.</p><p><strong>Why this matters more than LLM-based recommendations.</strong></p><p>LLM-based recommenders leverage <em>language</em> (prompts, descriptions, reviews) and pretrained world knowledge. HSTU leverages <em>actions</em>.</p><p>At scale, actions are a far denser and more informative signal than any natural language description of preferences.</p><p>A user’s last 500 interactions tell you more about what they want right now than any prompt they could type.</p><p><strong>The scaling law breakthrough.</strong> For the first time in recommender systems history, HSTU demonstrated power-law scaling with compute. The same pattern that made GPT possible. More compute = better recommendations, predictably.</p><p>This is the ChatGPT moment for RecSys, but it happened quietly because the architecture doesn’t generate text. It generates ranked lists.</p><p><strong>The cascade is dying.</strong> The traditional retrieve → lightweight rank → heavy rank → re-rank pipeline has been the default for a decade. HSTU challenges this by unifying retrieval and ranking into a single generative model.</p><p>Kuaishou’s OneRec took it further with session-wise list generation, generating interdependent sequences of videos instead of scoring items independently. Xiaohongshu’s GenRank is doing the same for ranking.</p><p>Every major platform (Google, ByteDance, Alibaba, Meituan) is racing to deploy some version of this paradigm.</p><p><strong>What this means for your stack.</strong> If you are still building retrieval and ranking as separate systems with independent feature pipelines, you are building the equivalent of a DLRM in 2016.</p><p>The next two years will be defined by teams figuring out how to unify these stages under a single generative model while keeping latency and serving costs under control. That’s the real engineering challenge.</p><p>Not whether to add a chatbot on top of your feed.</p><div><hr></div><h2>Real-Time Adaptation Trumps World Knowledge</h2><p>The most critical engineering challenge today is not how much “world knowledge” an LLM has, but how quickly the system can update its “user knowledge.”</p><p>A trillion-parameter model that knows everything about the world but only knows what the user liked <em>yesterday</em> is inferior to a small model that knows what the user liked <em>three seconds ago</em>.</p><p><strong>The state management problem.</strong> In the Two-Tower era, updating user embeddings in near real-time was solved. With LLMs, the context window is static. Injecting real-time behavior (clicks and skips from the current session) into an LLM requires complex RAG pipelines prone to latency spikes.</p><p>HSTU partially addresses this by design: the sequential input <em>is</em> the real-time signal. But serving long sequences at inference time introduces its own challenges.</p><p>Meta’s M-FALCON algorithm and recent work on context parallelism for HSTU show that even the best teams are still fighting this battle.</p><p><strong>The “Now” Factor.</strong> User intent is volatile. Someone switches from learning mode to entertainment mode in the span of two swipes. If the system relies on heavy, slow-to-update generative models, it misses these micro-shifts entirely.</p><p>The system that reacts instantly to a “skip” is more valuable than an agent that can write a sonnet about the video you just skipped.</p><p>Adapting to the user in real-time is more valuable than deep semantic understanding. Always has been. Always will be.</p><div><hr></div><h2>Bounded Personalization: Use GenAI for the Lens, Not the Content</h2><p>There is a dangerous allure in the concept of generative content: systems that create movies, music, or articles on the fly for a specific user. The “audience of one” vision. It ignores the social nature of media and the safety risks of hallucination.</p><p>The pragmatic step forward is <strong>bounded personalization</strong>: using GenAI to personalize the <em>presentation layer</em> within the strict boundaries of an existing catalog.</p><p><strong>Personalized framing.</strong> Don’t generate a new movie. Use an LLM to rewrite the synopsis or select the thumbnail of an existing movie based on the user’s interests. If a user loves romance, highlight the romantic subplot of an action movie in the description. The content stays vetted. The framing becomes personal.</p><p><strong>Safety in constraints.</strong> By operating within the boundaries of a fixed catalog, you eliminate the risk of an agent hallucinating offensive or nonsensical content. The AI contextualizes. It does not create.</p><p><strong>Explainability.</strong> Use small language models to generate “Why this?” explanations. This delivers the value of an agent (reasoning, contextualization) without the friction of a chat interface and without the risk of open-ended generation.</p><p>We don’t need to burn down the catalog to save the user. The winning strategy is GenAI as a dynamic, personalized <em>lens</em> through which users view the standard catalog.</p><div><hr></div><h2>The Real Playbook</h2><p>The RecSys 2025 keynote traced a path from Matrix Factorization to LLMs. The map for production engineers looks different.</p><p>The future is not replacing efficient ranking systems with slow, chatty agents.</p><p>It is hybrid vigor: keeping the ruthless efficiency and real-time speed of collaborative filtering, adopting the genuine generative breakthrough (HSTU-style sequential transduction, not GPT-style chatbots), and using LLMs surgically for the last mile of presentation and explanation.</p><p>Success won’t go to the company with the smartest agent. It will go to the system that can adapt to a user’s changing mood in under 100 milliseconds, while quietly running a trillion-parameter generative ranker underneath.</p><h2>References</h2><ol><li><p><a href="https://amatria.in/blog/recsyskeynote">2025 RecSys keynote</a></p></li></ol>
